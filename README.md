# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса (слоя View).
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Данные

#### Интерфейс IProduct (товар)
Интерфейс проверяющий наличие данных товара. Данный интерфейс используется для карточек в каталоге товаров и товаров в корзине товаров. Информация о товарах приходит с сервера, её можно найти в Product List -> Success, в массиве "items".

Поля интерфейса:
`id: string` - id товара, предоставляет сервер. Данные берутся из Product List -> Success, в массиве "items", ключ "id".

`title: string` - название товара, предоставляет сервер. Данные берутся из Product List -> Success, в массиве "items", ключ "title".

`image: string` - изображение на карточке товара, предоставляет сервер. Данные берутся из Product List -> Success, в массиве "items", ключ "image".

`category: string` - категория товара, предоставляет сервер. Данные берутся из Product List -> Success, в массиве "items", ключ "category".

`price: number | null` - цена товара, предоставляет сервер. Есть категория бесценных товаров, у которых тип null. Данные берутся из Product List -> Success, в массиве "items", ключ "price".

`description: string` - описание товаров (забавные), предоставляет сервер. Данные берутся из Product List -> Success, в массиве "items", ключ "description".

#### Интерфейс IBuyer (покупатель)
Интерфейс проверяющий наличие данных о покупателе.

`payment: TPayment | null` - способ оплаты покупателя.

`email: string` - электронная почта покупателя.

`phone: string` - телефон покупателя.

`address: string` - адрес покупателя.

#### Интерфейс IBuyerErrors (покупатель)
Интерфейс проверяющий валидность форм.

`payment?: string` - проверяет валидность поля payment.

`email?: string` - проверяет валидность поля email.

`phone?: string` - проверяет валидность поля phone.

`address?: string` - проверяет валидность поля address.

##### Тип TPayment
Тип, в котором хранятся способы оплаты.

Допустимые значения:
`"card"` - способ оплаты картой.

`"cash"` - способ оплаты наличными.

`getBasketProducts(): IProduct[]` - получение массива товаров, которые находятся в корзине.

### Слой представления (View)

Класс представления шапки сайта. Как и любой класс из слоя View, происходит от Component. Тут из интересного (значимого) только корзина со счётчиком товаров.

Поля класса:

`basketButton: HTMLButtonElement` - содержит ссылку на DOM button элемента кнопки корзины.
`counterElement: HTMLElement` - содержит ссылку на DOM span элемента счётчика кнопки корзины.

Методы класса:

`set counter(value: number)` - установка значения в счётчик counterElement.


#### Класс Gallery
Как и любой класс из слоя View, происходит от Component. Gallery -класс <main></main> тега, в который будут помещаться все карточки товаров.

Поля класса:

`catalogElement: HTMLElement` - содержит ссылку на DOM-элемент контейнера

Методы класса:

`set catalog(items: HTMLElement[]): void` - сеттер, в который приходит массив карточек. Он вытаскивает все карточки и помещает в поле catalogElement.


#### Класс Modal
Как и любой класс из слоя View, происходит от Component. Представляет из себя стандартное модальное окно без содержимого, имеющее только функцию закрытия и открытия окна этого. Вот. Ну и в него можно положить данные сеттером.

Поля класса:

`modalElement: HTMLElement` - содержит ссылку на DOM элемент модалки.
`closeButton: HTMLButtonElement` - содержит ссылку на DOM элемент кнопки.
`contentElement: HTMLElement` - содержит ссылку на DOM элемент div, в который будет помещён контент модального окна.

Методы класса:

`set content(element: HTMLElement): void` - сеттер, помещающий содержимое модалки, которое принимает в переменную element, в contentElement.
`open(): void` - открывает модальное окно.
`close(): void` - закрывает модальное окно.

### Слой коммуникации

#### Интерфейс IProductsResponse
Описывает объект, возвращаемый сервером при запросе списка товаров.
`total: number;` - количество товаров.
`items: IProduct[]` - сами товары.

#### Интерфейс IOrder
Описывает данные заказа, отправляемые на сервер. Расширяет интерфейс IBuyer и дополняет его общей стоимостью заказа
`total: number` - общая сумма заказа.
`items: string[]` - массив содержащий id товаров

#### Интерфейс IOrderResult 
Описывает ответ сервера после успешного оформления заказа.

`id: string` - id оформленного заказа.
`total: number` - итоговая стоимость.

#### Класс ConnectionAPI
Этот класс использует композицию, чтобы выполнить запрос на сервер с помощью метода get класса Api получает с сервера объект с массивом товаров.

Методы класса:
`getProducts()` - отправляет запрос на /product/ и возвращает объект с общим количеством товаров и массивом IProduct.
`createOrder(data)` - отправляет запрос на /order/ передавая данные заказа и возвращает результаты оформления заказа.
